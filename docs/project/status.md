# 项目状态

状态更新日期：2026-11-14；下文旧基线证据日期仍为2026-10-31。

本文区分新架构的设计与数值实验证据，以及旧 SystemVerilog dot16/Q2.34 基线的历史实现与验证状态。新架构已审核设计约束、验证边界及后续候选见[已确认约束](decisions.md)；旧设计的数值合同、接口和流水结构不默认继承。

## 新架构设计与证据

- **2026-11-14用户整体审核通过**：[IP_DESIGN](../design/new_architecture/IP_DESIGN.md)作为新架构后续Verilog实现与功能验证的设计基线，包含接口、数值、资源、周期及审查修订。当前阶段为设计已审核、RTL尚未开始；数值精度已确认采用误差指标报告与对照分析、不设统一通过阈值；功能验收仍要求RTL逐位符合数值合同，RTL/周期仿真、综合与时序验证仍待实施。

- 2026-11-14审查修订：明确Eeff、MAC有效位切片、scale宽域临时量及逐输入合法性检查；采用低8位旁路重构和MX符号异或检测/负端修正，补充X隔离及限定浮点非旁路的T!=-1断言。当前仍为三段ACC、D=3；四段ACC仅为实际时序紧张后的候选。未实现RTL、LZA或GLS。

- ACC周期设计已确认：组合读状态，S1对阶、S2加法、S3直接写回；同ctx的S1结果在E0采样、E2写回、E3再次采样，D=3且无写回旁路。前向各模式等固定延迟、保留气泡；全部计算流水valid为0作为排空判据。此为设计决定，RTL周期和时序尚未验证。

- MAC 核心边界已明确为 ACC 上下文状态寄存器及完整状态交接。内部固定 valid 流水；last 更新写回后标记完成，状态原槽保持至外部接收后释放。G=2 两路独立累加并共同交接，G=1仅更新ACC0。最终 FP32/INT32 转换及后续结果缓冲位于外部，核心不设置结果 FIFO 或 last 容量预留。已选三个配对事务槽、2-bit ctx_id、free/done位图与指定编号读取，状态无损打包为每路51位，接收后下一拍可复用。正常计算valid-only，外部保证合法调度，全部槽释放并排空后切换模式。不实现中途状态保存恢复或外部初值装载，仅允许完成状态读取；普通暂停保留原槽后续算。模式编码、复位及前向具体流水已通过整体审核；尚无周期模型或 RTL 验证。

- 共享乘法资源映射、局部截断归约、逐份贡献加后RNE40、多上下文交错及有限工作位补码数据通路已选定；位级数据通路为2位真实低位＋sticky、45位共享加法器、三段流水（D=3）、两条累加通路各3组上下文。位级模型与T0–T5检查已实现并在本地通过；RTL、共仿、综合与时序未开始；保存恢复不在实现范围，前向周期设计已通过整体审核。
- 入口转换、22-bit字段bundle、16前端group/块映射、2棵16输入树加41-bit最终加法器的归约结构、FP16 19/19 limb重构、FP4/INT4 offset-binary packing及N41/e_loc/h输出接口已确认；算术模型只做过Python只读算术核对（随机与枚举），RTL、共仿、综合和PPA未开始。
- 已有[局部对阶实验](../experiments/README.md)和[累加精度实验](../experiments/accumulation_precision.md)的数值模型与运行结果。局部实验用后续精确累计隔离局部损失；累加实验用精确dyadic相加后RNE评价状态精度。二者的配置、覆盖范围及结论边界见各自说明与[已确认约束](decisions.md)，不能替代有限工作位电路或全部合法输入域的验证。
- 新架构尚无已交接的RTL实现、端到端仿真、综合、时序或PPA证据；现有Verilog文件仍是旧基线的未完成改写。旧基线历史测试不作为新架构验证结果。
- [新架构IP设计文档](../design/new_architecture/IP_DESIGN.md)已按计算流程形成已审核的完整设计文档：总体接口、独立转换、乘法配对连接、MAX/对阶资源、两树归约、MX、ACC、完成读取、物理寄存器及验证场景。新补齐方案采用入口E0至E11写回的固定延迟、8条38-bit加24条32-bit对阶器、两棵分拍平衡树、同步复位和无效读取清零。整体审核已通过，未开始RTL。旧IP/RTL设计文档保持旧基线范围。

后续架构调整和任务顺序由用户确定；本轮未启动正式实验；文档检查及定向模型测试结果在本节补充，不能作为新增接口或流水的RTL验证。

本轮设计稿检查（2026-11-12）：文档链接检查通过；既有累加模型定向测试 `-k 't0 or t2 or t5'` 为 **14 passed、6 deselected**，日志见[acc_directed.log](../../results/verification/ip_design_review_20261112/acc_directed.log)。这只复核贡献规格化、ACC边界和范围，不覆盖新增前向流水或接口。未运行小p穷举、代表轨迹重放、正式数值实验、RTL或PPA；本轮未新增验证代码。

## 旧基线实现与证据缺口

- 当前完整链路由 testbench 连接；没有生产顶层封装、最终 FP32/其他目标格式转换器或结果端 ready。
- MX 非零贡献的数学指数 E 超出 1…254 仍是暂缓定义域。仿真断言用于拒绝该输入，不代表综合后的恢复策略。
- ACC 写回已定义 FTZ/Inf；这与 MX 输入越界边界不同，不能混为一种策略。
- PSUM 仿真采用 DesignWare 功能替身；本次没有真实库验证、综合、STA、面积、功耗或布局结果。
- 暂未形成旧基线 Q2.34 语义下的完整精度与 PPA 权衡评估。早期 `hwacc-v1` 实验与旧基线实现的系数、指数及舍入过程存在差异，不能直接把旧位宽结论当作旧基线 RTL 的精度保证。
- 图稿和章节已有草稿，但图中的输出保持槽等描述仍需在工程实现完善后复核。

## 文档的使用顺序

[已确认约束](decisions.md)是新架构已审核范围与验证边界的入口。[RTL 实现说明](../design/RTL_Design.md)用于理解旧 SystemVerilog 基线的代码事实，[架构设计](../design/IP_Design.md)用于理解旧基线的设计合同，[硬件验证说明](../../hardware/verification/README.md)用于理解旧基线的数值域与执行证据；这三份文档不构成新架构合同。发生差异时，先核对对应 RTL、独立模型和测试，再修订文档；涉及新架构语义时以 decisions.md 和用户后续确认为准。
