# 量化方法：从数值格式、异常值处理到 NPU 实际执行

> 本文是一节面向 NPU/AI 加速器与 LLM 部署研究的综述。逐篇证据表见[《量化算法列举》](量化算法列举.md)。文中本地引用给出 PDF 链接和物理页码，外部补充文献均链接到论文原文或标准/厂商官方资料。

## 1. 问题定义：量化的不是一个“模型位宽”，而是一条数据通路

LLM 量化常被简写成 W4A16、W8A8、W4A8KV4 或 FP8，但这只是 operand/存储标签。对硬件研究，更可靠的描述至少要写成：

\[
(b_W,\;g_W,\;s_W)\times(b_A,\;g_A,\;s_A)
\rightarrow b_{mul}\rightarrow b_{acc}\rightarrow b_{out},
\]

其中 `b` 是数据格式/位宽，`g` 是 scale 粒度，`s` 是静态或动态 scale；之后还要注明反量化、requantization、非线性和残差在哪种精度执行。

因此，本文采用三层口径：

- **保存格式**：权重/KV 在 HBM 中是 INT4、NF4、FP8，决定容量与带宽。
- **乘法格式**：MAC/MMA 实际接收 INT4、INT8、FP16、FP8 还是解码后的值，决定算力上限。
- **累加与输出格式**：INT32、FP16、BF16、FP32 或专用 fixed-point accumulator，决定数值稳定性和数据通路面积。

这个区分不是语义洁癖。GPTQ/AWQ 的 INT4 权重常在核内解码后与 FP16 A 计算；QLoRA 的 NF4 也先反量化到 BF16；QServe 的 W4 则先变成 INT8，再执行 INT8×INT8→INT32；Ascend W4A16 更要由 AIV 把 W4 完整转为 FP16，再交给 AIC 执行 FP16 GEMM。因此它们虽然都可写成“4-bit 权重”，硬件行为完全不同。[GPTQ](../../references/papers/2210.17323v2.pdf)（pp. 5–10）、[AWQ](../../references/papers/2306.00978v6.pdf)（pp. 4–8）、[QLoRA](https://arxiv.org/abs/2305.14314)、[QServe](../../references/papers/2405.04532v3.pdf)（pp. 5–8）、[Ascend W4A16](../../references/papers/2601.16536v2.pdf)（pp. 2–6）

## 2. 为什么不同位置走向了不同格式

### 2.1 权重：静态、可离线优化，首先走向 4 bit 甚至 2 bit

权重对所有请求共享，可离线统计和优化；decode 时每生成一个 token 都要读大权重矩阵，通常是 memory-bound。因此 W 是最早、也最容易降位的位置。演进大致是：

1. **INT8/定点统一量化**：早期 TPU 用 8-bit operand、16-bit product、32-bit accumulator，硬件规则且高吞吐，但 scale 粗、极低位精度差。[TPU](../../references/papers/1704.04760v1.pdf)（pp. 3–7）
2. **混合位宽与细粒度 scale**：HAQ 按硬件反馈逐层选 2–8 bit；VS-Quant 把 scale 粒度缩到 16–64 元素并量化 scale 本身。这说明“bit 数”和“scale 元数据/粒度”必须联合优化。[HAQ](../../references/papers/1811.08886v3.pdf)（pp. 2–5）、[VS-Quant](../../references/papers/2102.04503v1.pdf)（pp. 2–7）
3. **W-only 二阶/激活感知 PTQ**：GPTQ 用近似 Hessian 做逐列误差补偿，AWQ 用 activation magnitude 找 salient input channel 并等价缩放，主流配置稳定到 INT4-g128。[GPTQ](../../references/papers/2210.17323v2.pdf)（pp. 2–8）、[AWQ](../../references/papers/2306.00978v6.pdf)（pp. 3–6）
4. **非均匀码本与稀疏高精度修正**：QLoRA 的 NF4 用正态分位数码点提高冻结权重的 4-bit 信息利用率；SpQR 把少数 Hessian-sensitive W 作为稀疏高精度项；SeVeDo 用低秩高精度分支承接难量化结构。[QLoRA](https://arxiv.org/abs/2305.14314)、[SpQR](https://arxiv.org/abs/2306.03078)、[SeVeDo](../../references/papers/2512.12930v2.pdf)（pp. 2–5）
5. **服务友好的 W4A8/W4A4**：QServe 的 progressive W4 设计目标不是直接做 W4 MAC，而是规整、快速地恢复成 INT8 Tensor Core operand；Atom/QuaRot 则把 A 也降到 INT4，才真正使用 INT4×INT4。[QServe](../../references/papers/2405.04532v3.pdf)（pp. 4–8）、[Atom](https://arxiv.org/abs/2310.19102)、[QuaRot](https://arxiv.org/abs/2404.00456)

演变原因可以概括为：W 的离线自由度很大，所以研究先从“降低码长”转向“用二阶信息/激活敏感度决定怎样舍入”，再转向“量化格式必须与现有 MAC 的输入格式匹配”。在 NPU 上，若只有 FP16 Cube 而没有 INT4/INT8 混合矩阵单元，W4 主要是容量优化；若有 INT4 Tensor Core 或 block-scaled FP4 MMA，才可能同时得到算力收益。

### 2.2 Activation：动态、带异常通道，演进核心是控制局部动态范围

A 随 token、batch 和上下文改变，在线统计 scale 会增加 reduction、同步和读写；LLM 又存在少数幅值极大的 persistent channel。于是 activation 的演进不是简单从 16→8→4 bit，而是量化粒度和异常值变换的演进：

1. **per-tensor/per-token INT8**：ZeroQuant 采用 token-wise dynamic A，SmoothQuant 常用 per-token A；相比 per-tensor，单 token 的 scale 不被其他 token outlier 污染，但每 token 都要计算 amax。[ZeroQuant](https://arxiv.org/abs/2206.01861)、[SmoothQuant](../../references/papers/2211.10438v7.pdf)（pp. 3–6）
2. **异常通道分流**：LLM.int8() 把阈值以上的维度交给 FP16，只让普通 99.9% 进入 INT8。准确率好，但双路径、gather/scatter 和不规则访存使实现复杂。[LLM.int8()](../../references/papers/2208.07339v2.pdf)（pp. 2–5）
3. **平滑/等价迁移**：SmoothQuant 把 A channel 除以 `s`、W 对应乘 `s`，把 A 的难度迁到 W；AWQ 从保护 W 的角度使用相反但数学同类的通道缩放；OmniQuant 用可学习 LET/LWC 代替手调 `alpha` 和 clipping。[SmoothQuant](../../references/papers/2211.10438v7.pdf)（pp. 3–5）、[OmniQuant](https://arxiv.org/abs/2308.13137)
4. **混合 INT4/INT8 与通道重排**：Atom 将异常通道移到连续尾部，用 INT8 计算，主体 INT4；它保留分流精度优势，同时让 memory access 规则化。[Atom](https://arxiv.org/abs/2310.19102)
5. **旋转成近各向同性分布**：QuaRot 用随机 Hadamard，SpinQuant 学习正交 rotation，Quant.npu 仅保留可离线融合的 rotations。旋转不改变全精度函数，却把少数异常通道能量扩散到所有维度，推动 A4。[QuaRot](https://arxiv.org/abs/2404.00456)、[SpinQuant](https://arxiv.org/abs/2405.16406)、[Quant.npu](../../references/papers/2605.20295v1.pdf)（pp. 3–8）
6. **tile/block microscaling**：DeepSeek-V3 对 A 做 1×128 tile-wise E4M3 online scale；MX/NVFP4 把 scale 共享下沉到 32/16 元素。与旋转相比，这条路线不改变坐标系，而是缩短每个 scale 覆盖的统计范围。[DeepSeek-V3](https://arxiv.org/abs/2412.19437)、[OCP MX](https://www.opencompute.org/documents/ocp-microscaling-formats-mx-v1-0-spec-final-pdf)、[NVIDIA NVFP4](https://docs.nvidia.com/deeplearning/transformer-engine/user-guide/features/low_precision_training/nvfp4/nvfp4.html)

从硬件角度看，动态 A 的关键代价不是一个 `max` 指令，而是“读高精度 A→归约 amax→量化写回→GEMM 再读”的额外 HBM 往返。理想 NPU 应把 amax/scale/cast 融合到 LayerNorm/RMSNorm 输出或 DMA/TMA 搬运中，并让矩阵单元原生接收 group scale。DeepSeek-V3 对未来硬件的建议正是将 online cast 与数据搬运融合，并在 Tensor Core 内支持 inner-K group scale。[DeepSeek-V3](https://arxiv.org/html/2412.19437)

### 2.3 KV cache：从“模型参数”问题转为“时序状态”问题

KV 与 W 不同：它在运行中逐 token 生成，生命周期长，decode 时反复从 HBM 读取。长上下文/大 batch 下，KV 常比 W 更快成为容量和带宽瓶颈。其格式演进为：

| 阶段 | 代表方法 | K | V | 为什么这样分 |
|---|---|---|---|---|
| FP16/BF16 | 常规 serving | FP16/BF16 | FP16/BF16 | 无量化误差，但容量随 context 线性增长 |
| 2-bit 非对称、异粒度 | KIVI | per-channel INT2 + FP16 尾窗 | per-token INT2 + FP16 尾窗 | K 有固定 channel outlier；V 更随 token 变化 |
| 非均匀+稀疏异常值 | KVQuant | pre-RoPE per-channel INT2/3/4 | per-token INT2/3/4 | Fisher 码本与 1% FP16 outlier 追求更低位 |
| 服务规整 KV4 | QServe/Atom | per-head INT4 | per-head INT4 | INT4 更易打包和融合，精度/开销均衡 |
| 旋转 KV4 | QuaRot/SpinQuant | rotated INT4 | rotated INT4 | 消除固定异常方向，不保留高精度通道 |

KIVI 的关键发现不是“INT2 可用”本身，而是 K 与 V 不能共享同一种 axis：K 的极值在 channel 维稳定，应该 per-channel；V 缺少固定异常 channel，per-token 更合适。[KIVI](../../references/papers/2402.02750v2.pdf)（pp. 3–6, 12）KVQuant 进一步在 RoPE 前量化 K，以免旋转破坏 channel locality，并用非均匀码本、稀疏异常值与首 token 保护提高 2/3-bit 精度。[KVQuant](../../references/papers/2401.18079v6.pdf)（pp. 4–10）

但是绝大多数 KV2/KV4 是 **cache 保存格式**。decode kernel 载入低比特索引/整数后查表或乘 scale，QK、softmax、PV 仍在 FP16/FP32 计算。它们的收益来自少读 4–8 倍字节，只有当上下文/批量足够大、节省的内存时间超过 unpack/dequant 时才加速；QuaRot 的实测也显示小 batch 下 KV4 可能比 FP16 更慢。[QuaRot](https://arxiv.org/html/2404.00456)

### 2.4 非线性、归一化与残差：位宽下降最慢的位置

LayerNorm/RMSNorm 包含平方和、均值、倒数平方根；softmax 包含 max、exp、sum/div；GELU/SiLU 是非线性函数。它们往往：

- 对相对误差敏感，且存在长归约；
- FLOPs 占比低、内存占比高，降到 4/8 bit 对端到端吞吐的收益小于 GEMM；
- 位于 residual/branch 汇合处，需要统一 scale，否则会产生额外 rescale。

因此 FP16/BF16 mixed precision、FP8 Formats、MX、DeepSeek-V3、QuaRot 都保留高精度非线性/归一化。[Mixed Precision Training](../../references/papers/1710.03740v3.pdf)（pp. 3–5）、[FP8 Formats](../../references/papers/2209.05433v2.pdf)（pp. 3–6）、[MX](../../references/papers/2310.10537v3.pdf)（pp. 4–7）

演进中有两条例外路线：

1. **整数函数近似**：I-BERT 用整数多项式、移位与整数平方根完成 GELU/softmax/LayerNorm，实现端到端 integer-only BERT。[I-BERT](https://arxiv.org/abs/2101.01321)
2. **保留更宽整数中间量**：Quant.npu 把线性输出/KV 固定 INT8，但 SiLU 等用 INT16，既不回 FP，也承认非线性需要更大动态范围。[Quant.npu](../../references/papers/2605.20295v1.pdf)（pp. 4–8）

这说明非线性的合理演进并不一定是 INT8→INT4，而更可能是“FP16/BF16 fallback→INT16/LUT/多项式近似→与前后 requant 融合”。对于 NPU，是否拥有快速整数 reciprocal/sqrt/exp/LUT 往往比再增加一种 4-bit GEMM datatype 更决定端到端 integer-only 可行性。

### 2.5 训练：FP32→FP16/BF16→FP8→MX/FP4，但 accumulator 始终更宽

训练比推理多出 G、optimizer states、master weights、三类 GEMM（Fprop/Dgrad/Wgrad）与 collective communication。格式演进如下：

| 世代 | GEMM operands | 累加/输出 | master/optimizer | 主要解决的问题 |
|---|---|---|---|---|
| FP16 mixed precision | FP16 W/A/G | FP32 accumulation，输出 FP16 | FP32 | Tensor Core 加速；loss scaling 防小梯度下溢 |
| BF16 mixed precision | BF16 W/A/G | FP32 | FP32 | 用 8-bit exponent 避免 FP16 loss scaling |
| 早期 FP8 | E4M3 W/A、E5M2 G，或 E5M2 全局 | FP16/FP32 | FP16/FP32 | 以格式分工平衡范围与 mantissa |
| FP8-LM | FP8 compute/comm/部分状态 | 高精度输出/update | FP8/BF16/FP16 组合 | 把收益从 GEMM 扩到通信和状态 |
| MXFP6/MXFP4 | block-32 低比特 | BF16/FP32 scalar | FP32 | 用共享 exponent 把训练降到 6/4 bit |
| DeepSeek-V3 | E4M3 tile/block | 定期提升到 CUDA FP32 | FP32 master/G，BF16 moments | 细粒度 scale + 修补 Hopper 累加精度 |
| NVFP4 | E2M1 + block-16 E4M3 scale | 实现相关的宽累加 | 高精度状态 | 原生 block-scaled FP4 MMA |

FP16 mixed precision 的基础模式是 FP16×FP16→FP32，并保留 FP32 master W 与大归约；BF16 通过与 FP32 相同的 8-bit exponent 扩大动态范围，但同样用 FP32 accumulator。[Mixed Precision Training](../../references/papers/1710.03740v3.pdf)（pp. 1–5）、[BF16 Study](../../references/papers/1905.12322v3.pdf)（pp. 3–8）

早期 FP8 论文常在现有 GPU 上 **先 round 到 FP8、再转回 FP16/FP32 计算**。例如 2018 IBM FP8 与 2022 FP8 Formats 的数值实验不能被当作原生 FP8 吞吐证据。[IBM FP8](../../references/papers/1812.08011v1.pdf)（pp. 3–8）、[FP8 Formats](../../references/papers/2209.05433v2.pdf)（pp. 3–7）真正的 H100 FP8-LM/DeepSeek-V3 才使用原生 FP8 Tensor Core，但仍把输出、累加、master 或 optimizer 的敏感部分留在更高精度。[FP8-LM](https://arxiv.org/abs/2310.18313)、[DeepSeek-V3](https://arxiv.org/abs/2412.19437)

DeepSeek-V3 还揭示一个重要事实：API 宣称 FP32 accumulator，不代表 Tensor Core 内每个 partial accumulation 都有完整 FP32 有效精度。该实现报告 H800 FP8 MMA 内部约 14-bit 有效累加，因而每 128 个乘积把部分和搬到 CUDA Core FP32 register，乘 group scale 后继续累加。这是“operand FP8、内部 partial 约 14 bit、长期 accumulator FP32、output BF16/FP32”的四级路径。[DeepSeek-V3 §3.3](https://arxiv.org/html/2412.19437)

FP4 All the Way 用 NVFP4 数值覆盖 Fprop/Dgrad/Wgrad，并用 stochastic rounding 保护梯度，但其 Gaudi2 实验是软件模拟，不证明 FP4 MAC 加速。[FP4 All the Way](../../references/papers/2505.19115v2.pdf)（pp. 3–9）Blackwell 官方 `tcgen05.mma` 支持 NVFP4/MXFP4 block-scaled operand 后，FP4 才从训练 recipe 变成真实硬件输入格式。[NVIDIA CUTLASS Blackwell](https://docs.nvidia.com/cutlass/latest/media/docs/cpp/blackwell_functionality.html)

## 3. 硬件到底在算什么：典型数据通路对照

| 论文/配置标签 | HBM/SRAM 保存 | 矩阵单元输入 | 乘积/累加 | 输出/后续 | 主要收益 |
|---|---|---|---|---|---|
| GPTQ/AWQ W4A16 | W INT4，A FP16 | W 解包/反量化为 FP16；A FP16 | FP16×FP16，通常宽累加 | FP16 | 权重容量/带宽；未提高 FP16 MAC 峰值 |
| Ascend W4A16 | W INT4，A FP16 | AIV 先产 FP16 W；AIC 收 FP16/FP16 | FP16 GEMM，Split-K FP32 partial | FP16 | 容量收益，被 global workspace 往返削弱 |
| SmoothQuant W8A8 | W/A INT8 | INT8/INT8 | INT32 | 乘 scale→FP16 | 原生 INT8 Tensor Core 吞吐 |
| QServe W4A8 | W UINT4，A INT8 | W4 解包成 INT8；A INT8 | INT8×INT8→INT32 | epilogue→FP16 | W4 带宽 + INT8 算力 |
| Atom/QuaRot W4A4 | W/A INT4 | INT4/INT4 | INT32 | scale/cast FP16，group sum FP16 | 真正使用 INT4 Tensor Core |
| QLoRA NF4 | W NF4，A BF16 | W 反量化 BF16；A BF16 | BF16 GEMM，宽累加 | BF16 + LoRA | 训练显存，不是 NF4 算力 |
| KIVI/KVQuant KV2 | KV INT2/index | 查表/乘 scale成 FP16 | attention FP16/FP32 | softmax 高精度 | KV 容量/带宽 |
| QServe/Atom KV4 | KV INT4 | 载入后反量化 FP16 | attention FP16 | softmax FP16/FP32 | KV 带宽 |
| H100 FP8 | W/A/G E4M3/E5M2 | FP8/FP8 WGMMA | 内部低精度 partial；可提升至 FP32 | BF16/FP32 | 原生 FP8 算力与存储 |
| OCP MX | private FP4/6/8 + E8M0 scale | block-scaled operands | `scale_A scale_B × dot(private)` | 通常 FP32 | 细粒度动态范围与低比特 MMA |
| Blackwell NVFP4 | E2M1 + block-16 E4M3 scale + global FP32 scale | 原生 NVFP4 block-scaled MMA | 实现定义的宽 accumulator | 高精度输出/状态 | 原生 FP4 算力 |

这个表带来三个评价原则：

1. **先看 kernel，再看算法标签**。同为 W4，若设备只有 FP16 Cube，算法只能省带宽；若有 INT8 Tensor Core，可采用 QServe 式 W4→INT8；若有 INT4/NVFP4 MMA，才适合 W4A4/FP4。
2. **把 decode 与 prefill 分开**。小 batch decode 常是权重/KV带宽瓶颈，W-only/KV quant 已有价值；大 batch/prefill 转为 compute-bound 后，只有 A 也低比特、真正进入低比特 MMA 才能持续加速。
3. **把 quant/dequant 算进 roofline**。动态 amax、scale 元数据、unpack、group dequant、online Hadamard、跨核 workspace 都会吃掉理论速度。QServe 的融合、Atom 的通道重排融合、DeepSeek-V3 的 partial promotion 与 Ascend W4A16 的 AIV/AIC 协同都在解决这一问题。[QServe](../../references/papers/2405.04532v3.pdf)（pp. 6–9）、[Atom](https://arxiv.org/abs/2310.19102)、[Ascend W4A16](../../references/papers/2601.16536v2.pdf)（pp. 3–7）

## 4. 对抗异常值的六类方法

### 4.1 混合精度分流

把难量化值原样保留，是最直接的方法：LLM.int8 把 activation outlier channel 放到 FP16；SpQR 把 weight outlier 稀疏存成高精度；KVQuant 保留 1% KV outlier 与首个 token；Atom 把异常通道从 INT4 提升到 INT8。

优点是数值直观、不会让其他值承受异常值误差；缺点是稀疏索引、双路径、load imbalance 和额外 kernel。硬件若缺少规则的 mixed-precision tile，通常需要先重排成连续通道，Atom 就采用了这一做法。[LLM.int8()](../../references/papers/2208.07339v2.pdf)（pp. 3–5）、[SpQR](https://arxiv.org/abs/2306.03078)、[KVQuant](../../references/papers/2401.18079v6.pdf)（pp. 5–9）

### 4.2 平滑与等价尺度迁移

对线性层 `Y=XW`，插入可逆对角尺度 `S`：

\[
Y=(XS^{-1})(SW).
\]

SmoothQuant 选择 `S` 把 A outlier 迁到 W；AWQ 从 weight salience 出发放大重要 W channel 并逆缩 A；OmniQuant 的 LET 学习 scale/shift，LWC 学习 clipping。它们的共同点是变换可融合到 W、Norm 或前层，不改变全精度函数。[SmoothQuant](../../references/papers/2211.10438v7.pdf)（pp. 3–5）、[AWQ](../../references/papers/2306.00978v6.pdf)（pp. 3–5）、[OmniQuant](https://arxiv.org/abs/2308.13137)

局限是对角 scale 只能重分配各坐标的幅值，无法消除更复杂的相关结构；极低 A4/KV4 下因此逐渐转向正交 rotation。

### 4.3 正交旋转与 incoherent processing

若 `R^T R=I`，可以在相邻算子间插入 `R/R^T` 而保持函数等价。Hadamard 具有幅值均匀、快速 `O(n log n)` 的优点：

- QuaRot 随机选择 Hadamard/符号 rotation，覆盖 residual、FFN、attention 与 KV；
- SpinQuant 直接学习量化误差更小的正交 rotation；
- FlashAttention-3 同时旋转 Q/K，保持 `QK^T`，仅服务 FP8 attention；
- Quant.npu 只保留可离线吸收到 W 的 rotation，删除在线 rotation，换取移动 NPU 的静态整数执行。

旋转的代价不是零：不能离线融合的位置需要 online Hadamard，会增加延迟和高精度中间量；旋转还会改变 K 在 RoPE 前后的 locality。因此部署应把“数值收益”与“融合后是否仍有 runtime rotation”一起评估。[QuaRot](https://arxiv.org/abs/2404.00456)、[FlashAttention-3](../../references/papers/2407.08608v2.pdf)（pp. 5–8）、[Quant.npu](../../references/papers/2605.20295v1.pdf)（pp. 4–7）

### 4.4 细粒度 group/microscaling

将一个 scale 覆盖的元素数从 tensor/channel 缩到 128、32 或 16，可直接降低异常值对邻居的影响。它从 VS-Quant 的 per-vector scale，演进到 W4 group-128、DeepSeek 1×128/128×128，再到 OCP MX block-32 和 NVFP4 block-16。

代价是 scale 元数据和 inner-K group boundary。若每个 group dot 都要先转 FP16 再跨 group 相加，浮点操作和 register pressure 会显著上升；Atom 将这一步融合到 MMA pipeline，MXDOTP 则以单指令和 exact early accumulator 原生支持。[VS-Quant](../../references/papers/2102.04503v1.pdf)（pp. 3–6）、[MXDOTP](../../references/papers/2505.13159v1.pdf)（pp. 2–5）

### 4.5 非均匀码本、裁剪与二阶补偿

- GPTQ 用 Hessian-aware error feedback 决定每次舍入后的补偿；
- NF4 让 16 个码点适配近正态 W，而不是等距整数；
- KVQuant 用 Fisher-weighted per-layer non-uniform codebook；
- AWQ/OmniQuant/Atom 学习或搜索 clipping，主动牺牲少数极值来提高主体分辨率。

这些方法提升“同样 bit 数”的表达能力，却可能需要查表或复杂离线求解。硬件上，均匀 INT4 能直接进入 MMA；NF4/非均匀 code 通常要查表/反量化。因此信息论最优格式不必然是吞吐最优格式。

### 4.6 结构分解

SeVeDo 用 SVD 低秩高精度路径 + INT4 residual，SpQR 用稀疏高精度 outlier + 低比特稠密主体。它们都承认误差并非均匀分布，而是让高精度预算跟随结构。适合硬件的关键是高精度分支能否被规则化为小 GEMM/连续 tile；否则稀疏修正会受调度和访存开销限制。[SeVeDo](../../references/papers/2512.12930v2.pdf)（pp. 2–5）

## 5. 格式演进的根本原因

### 5.1 从“大动态范围”转向“局部共享动态范围”

BF16 用 8-bit exponent 保持全局范围；FP8 用 E4M3/E5M2 在 mantissa/range 间分工；MX/NVFP4 则把 exponent/scale 从逐元素改成小 block 共享。趋势不是 exponent 越来越少这么简单，而是把冗余 exponent bit 变为局部元数据，用更小 private element 换取乘法和存储效率。[FP8 Formats](../../references/papers/2209.05433v2.pdf)（pp. 2–5）、[OCP MX](<../../references/papers/OCP_Microscaling Formats (MX) v1.0 Spec_Final.pdf>)（pp. 9–15）、[NVIDIA NVFP4](https://docs.nvidia.com/deeplearning/transformer-engine/user-guide/features/low_precision_training/nvfp4/nvfp4.html)

### 5.2 从“模型统一格式”转向“位置和阶段特化”

W 静态且 decode 反复读取，适合 INT4/NF4；A 动态且 outlier 强，常需 INT8/FP8、per-token 或 rotation；KV 是时序状态，适合 INT2/4 但 attention 算术仍高精度；非线性 FLOPs 少且敏感，适合 FP16/BF16 或 INT16 近似；G/optimizer 要求范围和无偏更新，常用 E5M2、SR、BF16/FP32。因此“全模型一个 datatype”逐渐让位于 per-location precision map。

### 5.3 从“算法可量化”转向“系统可加速”

早期论文常报告 fake quant 精度；后续工作越来越重视 kernel：

- SmoothQuant 追求无 FP16 outlier branch 的规则 W8A8；
- AWQ/TinyChat 在解包和反量化上做融合；
- QServe 把 W4 映射到现有 INT8 Tensor Core；
- Atom/QuaRot 直接实现 INT4 GEMM；
- Quant.npu 删除在线 rotation/dynamic scale，迁就 NPU 静态图；
- DeepSeek-V3 把细粒度 scale 和 FP32 promotion 融入 WGMMA pipeline；
- MXDOTP/Blackwell 把 block scale 下沉到 ISA/矩阵单元。

这条演进说明，最终有价值的量化格式必须能让“低比特数据一直保持低比特到达 MAC”，并把 scale/unpack/requant 隐藏在搬运或 epilogue 中。

### 5.4 累加精度下降得最慢

INT8/INT4 通常累加到 INT32；FP16/BF16/FP8 通常目标是 FP32 accumulation；MX 的通用 dot 输出 FP32；MXDOTP 甚至用 95-bit exact fixed-point early accumulator 再舍入 FP32。原因是点积误差随 K 增长，训练 Dgrad/Wgrad 和 attention score 尤其敏感。[OCP MX](https://www.opencompute.org/documents/ocp-microscaling-formats-mx-v1-0-spec-final-pdf)、[MXDOTP](../../references/papers/2505.13159v1.pdf)（pp. 2–4）

因此未来硬件不应只营销 multiplier bit width，还应公开：partial-product 对齐、内部 truncation、accumulator 有效 mantissa、promotion 周期、saturation/rounding mode。DeepSeek-V3 在 H800 上的 14-bit 有效 partial accumulation 问题正说明 accumulator 规格会决定 FP8 训练能否稳定。[DeepSeek-V3](https://arxiv.org/html/2412.19437)

## 6. 面向 NPU/AI 加速器的设计与评估建议

### 6.1 建议的硬件能力优先级

1. **INT8×INT8→INT32 与 FP16/BF16×FP16/BF16→FP32 是基线**：覆盖 SmoothQuant、传统混合精度与多数 fallback。
2. **原生 INT4×INT4 或 W4A8 路径要明确**：若只能把 W4 解码为 FP16，宣称“支持 INT4”只代表存储；若支持 INT4→INT8 的无开销解包，可高效执行 QServe 类 W4A8。
3. **block-scaled MMA 接口**：矩阵单元接收 private elements 与 scale，支持 inner-K 每 16/32/128 元素改变 scale，并在片内做 scale product 与宽累加。
4. **在线量化融合**：RMSNorm/LayerNorm 输出、DMA load、amax reduction、cast、pack 应一遍完成，避免 HBM round trip。
5. **整数非线性原语**：宽整数 reduction、LUT、shift、integer sqrt/reciprocal/exp approximation 与低成本 requant，是端到端 NPU integer pipeline 的必要条件。
6. **混合精度 tile 与规则稀疏修正**：支持少量 INT8/FP16 channel 与 INT4 主体在同一 tile/指令内计算，减少 LLM.int8/Atom/SpQR 类双路径开销。
7. **透明 accumulator 规格**：公开内部有效精度和 rounding，允许软件控制 promotion interval。

### 6.2 评估一篇量化论文时应记录的最小字段

| 类别 | 必须记录 |
|---|---|
| 模型/阶段 | pretraining、finetuning、prefill、decode；模型大小、batch、context |
| W | datatype、对称/非对称、group/channel 粒度、scale/zero datatype、静/动态 |
| A/G | datatype、per-token/tile/block、online amax、SR/RNE、缓存格式 |
| KV | K/V 分别的 axis/group、pre/post-RoPE、残留高精度窗口/outlier |
| 非线性 | Layer/RMSNorm、softmax、GELU/SiLU、residual 的真实精度 |
| 数据通路 | 保存→解包/反量化→MAC operand→partial accumulator→输出→requant |
| 异常值 | 分流、平滑、旋转、裁剪、非均匀码本、低秩/稀疏修正 |
| 性能证据 | fake quant、模拟器、单 kernel、真实端到端；硬件型号与 kernel 库 |
| 元数据/开销 | scale/zero/codebook bits，online reduction，workspace，layout duplication |

如果论文没有报告其中某项，应写“未说明”，不能从算法符号补出硬件事实。尤其要警惕三种错误推断：

- FP8 tensor ≠ 原生 FP8 arithmetic；
- FP32 output/accumulator API ≠ 所有内部 partial 都是完整 FP32；
- 4× 权重压缩 ≠ 4× 端到端加速。

### 6.3 按目标选择方法

| 目标平台/瓶颈 | 优先方法 | 不应忽略 |
|---|---|---|
| 无 INT4 MAC、decode memory-bound | GPTQ/AWQ W4A16 | 反量化带宽、kernel fusion；prefill 不一定加速 |
| 有 INT8 Tensor Core、希望权重 4 bit | QServe W4A8 | W4→INT8 转换是否片内；A8 动态量化开销 |
| 有 INT4 Tensor Core、大 batch serving | Atom/QuaRot W4A4KV4 | online A quant/rotation、INT32/FP16 group accumulation |
| 移动 NPU、静态图/纯整数优先 | SmoothQuant/Quant.npu/I-BERT 类 | per-tensor static A 的精度代价；INT16 非线性支持 |
| 长上下文、小 batch decode | KIVI/KVQuant/QServe KV4 | K/V axis、反量化融合、短上下文可能负收益 |
| H100 FP8 训练 | FP8-LM/DeepSeek-V3 类 | scale granularity、内部累加有效精度、promotion |
| Blackwell FP4 训练 | NVFP4 recipe/FP4 training | block/global scale 元数据、master/optimizer 仍高精度 |
| 微调显存而非推理算力 | QLoRA NF4 | compute 仍 BF16；LoRA/optimizer/activation 占用 |

## 7. 结论

量化格式的主线不是简单的 FP32→FP16→INT8→INT4。更准确的演进是：

1. **数值表示**从逐元素宽 exponent，走向 per-channel/per-token，再走向 block-16/32/128 的 microscaling；
2. **误差控制**从 clipping 和高精度兜底，走向二阶补偿、等价平滑、正交旋转、稀疏/低秩结构分解；
3. **量化位置**从 W 扩到 A、G、KV、通信与 optimizer，但非线性和累加仍普遍保留更宽格式；
4. **系统实现**从 fake quant 验证走向 kernel/ISA/数据搬运协同，低比特保存只有在低比特 operand 真正进入 MAC 且 scale/unpack 被融合时，才会转化为算力收益；
5. **硬件指标**也应从“支持 FP8/INT4”升级为完整的 operand、scale 粒度、partial accumulation、output 与 requantization 规格。

对于 NPU 研究，最重要的判断不是“某算法精度是否达到 4 bit”，而是：它是否允许静态/可融合 scale，是否仍有在线旋转和 FP fallback，W/A/KV 的低比特数据能否原样进入矩阵单元，累加器是否足够宽，以及这些选择在 prefill 与 decode 的 roofline 上分别消除了哪个瓶颈。
