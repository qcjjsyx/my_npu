> 整理日期：2026-07-16

## 0. 阅读口径

本文刻意区分三个经常被混写的概念：

1. **存储/传输格式**：HBM、DRAM、片上 SRAM 或通信链路中保存的位模式，例如 INT4、NF4、FP8 E4M3。
2. **乘法输入格式**：真正送入 MAC/MMA 的两个操作数。例如“W4A16”可能先把 INT4 权重解码成 FP16，再执行 FP16×FP16。
3. **累加/输出格式**：乘积部分和与 GEMM 输出的精度，例如 INT8×INT8→INT32、FP8×FP8→FP32。论文写“FP8 计算”不等于每一步都是 8 bit。

约定：W=weight，A=activation，G=gradient，KV=KV cache；“—”表示论文没有量化该位置；“未说明”表示论文没有给出足以确定的实现细节，本文不作推断。页码均指 PDF 物理页。

## 2. `paper/` 本地文献逐篇整理

### L01. Fast Exact Summation Using Small and Large Superaccumulators（2015）— 累加背景，非量化算法

来源：[本地 PDF](../../references/papers/1505.05571v1.pdf)

- **为什么提出**：普通浮点归约受顺序影响并累积舍入误差，目标是得到可复现的精确和。
- **方法**：用 small/large superaccumulator 精确吸收浮点加数，最后只舍入一次。
- **位置/格式**：不改变 W/A/KV/非线性格式；研究对象是浮点求和/归约。
- **实际计算**：整数化的超累加器与最终浮点舍入，不是低比特张量乘法。
- **与量化的关系**：说明“乘数很低比特”也不能忽略累加器设计；但它本身不应列为 LLM 量化算法。（PDF pp. 1–6）

### L02. In-Datacenter Performance Analysis of a Tensor Processing Unit（2017）— 硬件基线

来源：[本地 PDF](../../references/papers/1704.04760v1.pdf)

- **为什么提出**：数据中心推理需要高吞吐、低能耗与可预测延迟。
- **量化/格式**：模型由软件量化为 8-bit 整数；该论文没有提出新的量化标定算法。
- **实际计算**：65,536 个 8-bit 乘法器；8-bit 操作数产生 16-bit 乘积并进入 32-bit 累加器。8-bit W/16-bit A 也可执行，但吞吐约减半。
- **位置**：主要是矩阵乘 W/A；非线性在向量/标量单元执行，KV cache 尚非论文对象。
- **关键结论**：INT8 模型仍依赖 INT32 累加，存储位宽不能代替数据通路描述。（PDF pp. 3–7）

### L03. Loom: Exploiting Weight and Activation Precisions to Accelerate CNNs（2017）— 位串行硬件

来源：[本地 PDF](../../references/papers/1706.07853v2.pdf)

- **为什么提出**：固定 16-bit datapath 浪费了不同层、不同输入实际需要的有效位。
- **方法**：离线 profiling 权重位宽，运行时按 256 个 activation 一组检测所需位宽；位串行地只执行有效 bit-plane。
- **位置/格式**：W/A 为层/组可变的定点整数（论文示例约 5–13 bit A、7–10+ bit W），非线性不属核心贡献，KV 不适用。
- **实际计算**：1-bit×1-bit 部分积经移位和累加合成整数乘法，而非先还原到 FP16。
- **异常值**：没有平滑/旋转；动态组位宽本质上用更多 bit 容纳宽动态范围。（PDF pp. 2–7）

### L04. SCNN: An Accelerator for Compressed-sparse Convolutional Neural Networks（2017）— 稀疏性硬件

来源：[本地 PDF](../../references/papers/1708.04485v1.pdf)

- **为什么提出**：剪枝后的 W 与 ReLU 后的 A 都高度稀疏，零值乘法和数据搬运应被消除。
- **方法**：压缩存储稀疏 W/A，只对非零笛卡尔积执行乘法并散射累加。
- **位置/格式**：重点是稀疏编码，不是新量化器；实现采用 16-bit 乘法器、24-bit 累加器。
- **非线性**：ReLU 产生 activation sparsity；KV 不适用。
- **关键结论**：稀疏和量化正交，不能把“压缩格式”都归为数值量化。（PDF pp. 2–6）

### L05. Mixed Precision Training（2017）

来源：[本地 PDF](../../references/papers/1710.03740v3.pdf)

- **为什么提出**：FP16 能减半存储并利用 Tensor Core，但动态范围窄，直接训练会造成小梯度下溢和更新丢失。
- **方法**：W/A/G 前反向使用 FP16；保留 FP32 master weight，由 FP32 optimizer 更新；用 loss scaling 把小梯度移入 FP16 可表示范围。
- **位置/格式**：卷积/GEMM 输入 FP16，输出通常 FP16；大归约、BatchNorm 统计、softmax 等敏感算子用 FP32。
- **实际计算**：V100 Tensor Core 执行 FP16×FP16、FP32 累加；不是 FP16 累加。
- **异常值/稳定性**：不是 LLM 异常通道问题，主要通过 loss scaling 和 FP32 master/归约对抗动态范围与累加误差。（PDF pp. 1–5）

### L06. Bit Fusion: Bit-Level Dynamically Composable Architecture（2017）— 可变位宽硬件

来源：[本地 PDF](../../references/papers/1712.01507v2.pdf)

- **为什么提出**：网络各层对精度需求不同，固定 INT8/INT16 阵列无法把降位宽直接转化为吞吐。
- **方法**：把 2-bit BitBrick 动态融合为 2/4/8/16-bit 乘法器，支持 W/A 独立位宽。
- **实际计算**：2-bit 小乘法、移位与层级累加构成更宽整数乘法；没有先转 FP16。
- **算法边界**：论文提供执行 substrate，不决定 scale、zero-point、校准或异常值处理，因此不是量化算法。（PDF pp. 2–7）

### L07. HAQ: Hardware-Aware Automated Quantization（2018）

来源：[本地 PDF](../../references/papers/1811.08886v3.pdf)

- **为什么提出**：同一 bit 配置在不同硬件上的延迟/能耗不同，按 FLOPs 或模型大小选择混合精度会偏离真实目标。
- **方法**：DDPG agent 逐层选择 W/A 2–8 bit；用真实硬件/模拟器的 latency、energy 作为约束与奖励，短暂微调后评估精度。
- **量化格式**：对称均匀定点，KL divergence 选 clipping range；逐层混合位宽。KV/Transformer 非论文对象。
- **实际计算**：取决于 BitFusion/BISMO 等整数可变精度后端。
- **异常值**：以 clipping 和 bit allocation 吸收，不含平滑/旋转。（PDF pp. 1–5）

### L08. Training Deep Neural Networks with 8-bit Floating Point Numbers（2018）

来源：[本地 PDF](../../references/papers/1812.08011v1.pdf)

- **为什么提出**：进一步降低训练 W/A/G 的存储、带宽和乘法成本，同时保持 FP 的动态范围优势。
- **方法/格式**：前向、反向及权重梯度 GEMM 的 W/A/error/gradient 使用 FP8 `(1,5,2)`（E5M2）；累加和权重更新使用定制 FP16 `(1,6,9)`；末层与部分敏感位置保留 FP16；loss scale=1000。
- **实际计算**：实验在 GPU 上做位准确软件模拟，并没有原生 FP8 Tensor Core；论文设想的硬件是 FP8 乘法、FP16 分块累加。
- **稳定性**：每约 64 项形成 chunk 再累加，避免 swamping；权重更新使用浮点 stochastic rounding。
- **位置**：KV 不适用；softmax/末层等敏感算子不强制 FP8。（PDF pp. 1–9）

### L09. A Study of BFLOAT16 for Deep Learning Training（2019）

来源：[本地 PDF](../../references/papers/1905.12322v3.pdf)

- **为什么提出**：FP16 的 5-bit exponent 容易溢出/下溢，需要 loss scaling；BF16 保留 FP32 的 8-bit exponent，降低训练调参成本。
- **格式**：W/A 可存 BF16；FP32 master weight、optimizer、bias；GEMM 输出再舍入为 BF16。BatchNorm、ReLU、tanh、sigmoid 可用 BF16 输入，敏感实验保留 FP32。
- **实际计算**：BF16×BF16→FP32 累加；论文部分环境为软件 bit-accurate emulation，另讨论 AVX512_BF16 原生点积。
- **异常值**：靠大 exponent 范围而非通道变换；KV 不适用。（PDF pp. 3–8）

### L10. VS-Quant: Per-vector Scaled Quantization for Accurate Low-Precision Neural Network Inference（2021）

来源：[本地 PDF](../../references/papers/2102.04503v1.pdf)

- **为什么提出**：per-tensor/per-channel scale 仍让一组内的小值受极值支配；但逐元素 scale 元数据和硬件成本过高。
- **方法**：把 W/A 切成 16–64 元素向量，每向量对称均匀整数；细粒度 scale 自身再量化为低比特整数，并由较粗 FP scale 还原，形成两级 scale。
- **格式/位置**：示例包含 W4A4 CNN、W4A8 BERT；W 静态、A 可动态；KV/非线性不是重点。
- **实际计算**：向量内整数 dot/整数累加，scale 乘法移到 dot 外；粗尺度在更高精度域应用。
- **异常值**：缩小 scale 共享范围，是后续 group quant/microscaling 的先驱，不用旋转。（PDF pp. 1–7）

### L11. FAST: DNN Training Under Variable Precision Block Floating Point（2021）

来源：[本地 PDF](../../references/papers/2110.15456v1.pdf)

- **为什么提出**：固定精度 BFP 训练要么精度不足，要么浪费；训练早期和不同层需要的 mantissa 位数不同。
- **方法**：W/A/G 按默认 16 元素共享 exponent，mantissa 从 2/4 bit 等低位开始，随层和训练阶段自适应增加；gradient 使用 stochastic rounding。
- **实际计算**：2-bit mantissa chunk 的 fMAC，多 pass 组合高位宽；跨 BFP group 的部分和进入浮点累加器。
- **非线性/KV**：未提出专门量化；通常留在浮点数据通路。
- **异常值**：共享 exponent 缩小局部动态范围；无平滑/旋转。（PDF pp. 1–8）

### L12. LLM.int8(): 8-bit Matrix Multiplication for Transformers at Scale（2022）

来源：[本地 PDF](../../references/papers/2208.07339v2.pdf)

- **为什么提出**：大于约 6.7B 参数后出现跨 token 持久的 activation outlier channel，纯 W8A8 的一个大 scale 会淹没普通值。
- **方法**：vector-wise absmax：A 每行、W 每列动态/静态量化为 INT8；绝对值超过阈值（典型 6）的特征维单独抽出。
- **位置/格式**：线性层/attention projection 的普通部分 W8A8；约 0.1% 异常维 W/A 用 FP16。LayerNorm、softmax、GELU 及块间张量为 FP16；不量化 KV cache。
- **实际计算**：普通部分 INT8×INT8→INT32，按 FP16 scale 外积反量化；异常子矩阵执行 FP16 GEMM；两路在 FP16 合并。
- **异常值**：显式混合精度分流，准确但会带来索引和双 kernel 开销。（PDF pp. 2–6）

### L13. FP8 Formats for Deep Learning（2022）

来源：[本地 PDF](../../references/papers/2209.05433v2.pdf)

- **为什么提出**：统一训练/推理 FP8 交换格式，并在范围与有效数字之间分工。
- **方法/格式**：E4M3（最大有限值 448）用于 W/A，E5M2（范围更大）用于 G；每 tensor 高精度 scale，溢出饱和。PTQ 中 W per-channel、A per-tensor，GEMM 与 attention BMM 输入可 E4M3。
- **非线性**：GEMM 输出、归一化、softmax、逐元素非线性通常保留 FP16/BF16/FP32。
- **实际计算警告**：论文实验把输入 round 到 FP8 后转回 FP16/BF16 计算，是 **FP8 数值模拟**；不能据此声称测得原生 FP8 硬件吞吐。
- **异常值**：主要靠 scale 与 E4M3/E5M2 分工，无旋转。（PDF pp. 2–8）

### L14. GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers（2022）

来源：[本地 PDF](../../references/papers/2210.17323v2.pdf)

- **为什么提出**：超大模型 QAT 成本高，朴素 RTN 在 3/4 bit 尤其小模型上误差明显；需要一次校准、可在数小时内完成的 W-only PTQ。
- **方法**：逐层最小化输出重构误差；用输入二阶矩近似 Hessian，按列量化后利用逆 Hessian 把误差补偿到剩余权重；Cholesky 与 block update 提升可扩展性。
- **格式/位置**：W 对称/非对称 INT2/3/4，常用 per-row 与 group scale；A、KV、非线性保持 FP16；embedding/output head 可保留高精度。
- **实际计算**：自定义 kernel 从低比特存储解包/反量化权重，与 FP16 vector/matrix 计算。它节省权重带宽，但不是 INT4×INT4 Tensor Core 路径。
- **异常值**：没有显式平滑/旋转；二阶误差传播保护敏感方向。（PDF pp. 2–10）

### L15. SmoothQuant: Accurate and Efficient Post-Training Quantization for Large Language Models（2022/2023）

来源：[本地 PDF](../../references/papers/2211.10438v7.pdf)

- **为什么提出**：activation outlier 集中在固定输入通道，使 W8A8 的 A 比 W 难量化；LLM.int8 的 FP16 异常分支降低硬件规则性。
- **方法**：使用等价变换 `X_hat = X diag(s)^-1`、`W_hat = diag(s) W`，其中 `s_j` 由该通道 A/W 最大值及迁移强度 `alpha` 决定；scale 可离线融合进 LayerNorm/前层。
- **格式/位置**：线性层和 attention BMM 的 W/A 为对称 INT8；常用 per-channel W、per-token 动态 A。LayerNorm、softmax、GELU、残差为 FP16；KV cache 未量化。
- **实际计算**：CUTLASS INT8 GEMM，INT8×INT8→INT32，再乘 scale 输出 FP16。
- **异常值**：不是删掉异常值，而是把 A 的量化难度“平滑”迁移到更易量化的 W。（PDF pp. 2–6）

### L16. AWQ: Activation-aware Weight Quantization for LLM Compression and Acceleration（2023/2024）

来源：[本地 PDF](../../references/papers/2306.00978v6.pdf)

- **为什么提出**：W-only 低比特能降低 decode 权重带宽，但逐权重误差并不等价于模型重要性；直接保留 1% FP16 权重又会造成不规则 kernel。
- **方法**：用 calibration activation 的平均幅值识别 salient input channel；把这些通道的 W 放大、A 等价缩小，再做 group-wise INT3/4；搜索缩放指数并配合 weight clipping。
- **格式/位置**：典型 W4-g128/A16；只量化线性层 W，A/KV/LayerNorm/softmax/GELU 保持 FP16。
- **实际计算**：TinyChat kernel 从 INT4 存储解包并在主循环反量化到 FP16，与 FP16 A 计算；核心收益首先是带宽/容量，不是原生 INT4×FP16 MAC。
- **异常值**：activation-aware 等价 scaling，保护约 1% salient channel，但保持规整的全低比特权重布局。（PDF pp. 3–8）

### L17. EIE: Efficient Inference Engine on Compressed Deep Neural Network（2023 retrospective）— 历史压缩硬件

来源：[本地 PDF](../../references/papers/2306.09552v1.pdf)

- **为什么提出**：回顾 Deep Compression/EIE 如何同时利用剪枝、权重共享与片上存储。
- **量化格式**：权重以 4-bit codebook index 存储，码本项/解码值为 16 bit；A 为 16 bit，并伴随稀疏编码。
- **实际计算**：W4 是索引存储格式，计算前查表得到 16-bit W，再执行 16-bit 算术。
- **非线性/KV**：非线性不属核心量化创新，KV 不适用。
- **关键结论**：典型例子证明“4-bit model”可能只是压缩率，不代表 4-bit 乘法。（PDF pp. 1–5）

### L18. Efficient Post-Training Quantization with FP8 Formats（2023）

来源：[本地 PDF](../../references/papers/2309.14592v2.pdf)

- **为什么提出**：E4M3/E5M2 并非对所有 tensor 都最优；PTQ 还需要研究 scale 粒度、静动态策略以及非 GEMM 算子能否进入 FP8。
- **方法/格式**：比较 E5M2、E4M3、E3M4；默认 W per-channel、A per-tensor，静态 scale，必要时动态。NLP 最佳混合常为 A-E4M3/W-E3M4；可把 Add/Mul/Norm 等逐步扩到 FP8。
- **位置**：W/A 及部分逐元素算子；KV 没有专门研究。CNN 首末层可保留高精度；NLP 使用 SmoothQuant。
- **实际计算警告**：整篇使用 FP32 hardware 上的软件 FP8 emulation，结论是数值可行性，不是原生 FP8 kernel 性能。
- **异常值**：混合格式给 range-bound tensor 更多 exponent、给 precision-bound tensor 更多 mantissa，并以 SmoothQuant 平滑 A。（PDF pp. 2–9）

### L19. Microscaling Data Formats for Deep Learning（2023）

来源：[本地 PDF](../../references/papers/2310.10537v3.pdf)

- **为什么提出**：单一 tensor scale 无法同时覆盖异常值与主体分布；逐元素 FP 又把大量 bit 花在重复 exponent 上。
- **方法/格式**：32 元素共享 8-bit E8M0 power-of-two scale；元素用 MXFP8(E4M3/E5M2)、MXFP6(E2M3/E3M2)、MXFP4(E2M1) 或 MXINT8。训练示例含 MXFP6 W/A/G，以及 MXFP4 W + MXFP6 A/G。
- **位置**：前向、Dgrad、Wgrad 的 matmul/conv 输入量化为 MX；LayerNorm、softmax、GELU、residual add 和 master weight 用 BF16/FP32。
- **实际计算**：每块先做低比特点积，再乘两个共享 scale，输出 BF16/FP32 scalar。论文用 custom CUDA **模拟** MX，不是原生 MX 硬件测速。
- **异常值**：block-32 microscaling 缩短共享动态范围；量化与转置不交换，训练时往往要分别维护 row-wise/column-wise 布局。（PDF pp. 2–8）

### L20. KVQuant: Towards 10 Million Context Length LLM Inference with KV Cache Quantization（2024）

来源：[本地 PDF](../../references/papers/2401.18079v6.pdf)

- **为什么提出**：长上下文 decode 的 KV cache 容量和读带宽随序列线性增长；统一均匀 INT2 会被 K 的通道异常值破坏。
- **方法**：K 按通道、V 按 token；K 在 RoPE **之前**量化，kernel 中反量化并施加 RoPE。根据 Fisher/敏感度学习 per-layer 非均匀 `nuqX` 码本，支持 2/3/4 bit。
- **格式/位置**：KV 主体低比特 index；约 1% outlier 以 FP16 稀疏结构保留，首个 attention-sink token 保留 FP16。W/A/非线性默认 FP16，可与 W-only 方法组合。
- **实际计算**：kernel 查表得到 FP16 值，结合稀疏 FP16 outlier 完成 QK/AV 的 matrix-vector；低比特主要节省 KV 存储/带宽，并非 INT2 attention MAC。
- **异常值**：non-uniform codebook + dense/sparse 混合 + 首 token 保护。（PDF pp. 4–10）

### L21. KIVI: A Tuning-Free Asymmetric 2bit Quantization for KV Cache（2024）

来源：[本地 PDF](../../references/papers/2402.02750v2.pdf)

- **为什么提出**：KV INT2 可以大幅延长 batch/context，但 K 与 V 的统计结构不同；同一 per-token quantizer 不适合二者。
- **方法**：非对称均匀 INT2、group size 32；K 的异常值在固定通道上持久，因此 K per-channel（沿 token 分组）；V 没有固定异常通道，因此 V per-token（沿 channel 分组）。
- **格式/位置**：历史 K/V INT2，最近 residual window（通常不超过 128 token）FP16；W/A/softmax 保持 FP16。
- **实际计算**：融合 dequantization 与 attention matmul；量化值解码后参与高精度 attention，INT2 是 cache 格式而非 INT2 MAC。
- **异常值**：通过 K/V 不同粒度及 FP16 尾窗处理，不用旋转。（PDF pp. 3–7, 12）

### L22. QServe: W4A8KV4 Quantization and System Co-design for Efficient LLM Serving（2024）

来源：[本地 PDF](../../references/papers/2405.04532v3.pdf)

- **为什么提出**：W4A16 不能使用整数 Tensor Core 峰值，W8A8 又没有把权重/KV 带宽压到 4 bit；需要量化算法与 kernel/调度联合设计。
- **QoQ 权重**：先用 per-channel symmetric INT8 保护动态范围（裁剪到约 `[-119,119]`），再在其上做 per-group asymmetric UINT4，scale 用 UINT8、zero 用 UINT4。运行时 W4 解包/重映射成 INT8。
- **位置/格式**：线性层 W4A8；KV per-head dynamic INT4，scale/zero 为 FP16；块边界、LayerNorm、SiLU/GELU、softmax 为 FP16。
- **实际计算**：主 GEMM 是 INT8×INT8 Tensor Core→INT32，epilogue 反量化到 FP16；因此 W4 是存储格式，乘法输入是 INT8。attention 载入 KV4 后反量化，用 FP16 CUDA core 计算。
- **异常值**：block-input Hadamard、block-output smoothing、activation-aware channel reordering/clipping；SmoothAttention 缩小 K 通道并反向放大 Q，RoPE 成对通道共享 scale。（PDF pp. 3–9）

### L23. FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision（2024）

来源：[本地 PDF](../../references/papers/2407.08608v2.pdf)

- **为什么提出**：Hopper 的 WGMMA/TMA 可被异步流水利用；FP8 attention 的 per-tensor scale 又容易被 Q/K outlier 拉大。
- **方法/格式**：Q/K/V 采用 FP8 E4M3 block quantization；对 Q、K 同时乘随机符号对角阵与 Hadamard 正交变换，保持 `QK^T` 不变并摊平异常值。
- **位置**：只针对 attention 核；softmax、在线最大值/归一化重标度与关键中间量保留 FP32/FP16，W 与通用非线性不在范围内。
- **实际计算**：H100 FP8 WGMMA/Tensor Core 执行 QK/PV 乘法，部分和采用 FP32 accumulator 路径；softmax 在 CUDA/MUFU 高精度路径执行。
- **异常值**：incoherent processing（随机符号+Hadamard），可与上游算子融合。（PDF pp. 2–8）

### L24. Hardware Converter from FP32 to MX Formats（2024）— 格式转换硬件

来源：[本地 PDF](../../references/papers/2411.03149v1.pdf)

- **为什么提出**：MX 的运行时量化需要先找 block max exponent、生成共享 scale、再舍入各元素，若由软件多 pass 完成会抵消低比特收益。
- **方法/格式**：组合逻辑把 32 个 FP32 输入转换为 MXFP8/6/4 或 MXINT8；共享 E8M0 scale。
- **实际计算**：max-exponent tree→scale generation→private-element rounding；FPGA 原型无中间存储。
- **算法边界**：不决定模型哪些 tensor 用何种 MX，也不提供校准/异常值算法；属于数据格式转换单元。（PDF pp. 1–6）

### L25. Datacenter TCO Analysis of LLM Inference with FP8（2025）— 系统分析

来源：[本地 PDF](../../references/papers/2502.01070v4.pdf)

- **为什么提出**：理论 FP8 峰值不等于在线服务成本，thin GEMM、量化开销、累加精度及厂商实现都会影响 TCO。
- **格式观察**：H100/H200 与 Gaudi 支持 E4M3/E5M2；W 通常离线量化，A 动态量化；per-token 或 128×128 等细粒度 scale 改善精度但增加在线成本。
- **实际计算**：论文报告 Hopper FP8 Tensor Core 内部累加有效精度受限，并讨论周期性提升/FP32 累加；Gaudi 路径采用 FP32 accumulation。该结论是论文对具体平台/软件栈的测量，不宜外推到所有 GPU。
- **算法边界**：不提出新的量化器；价值在于提醒同时报告 shape、利用率、量化核和 accumulator。（PDF pp. 3–10）

### L26. MXDOTP: An Instruction for Efficient Microscaling Dot Products（2025）— ISA/硬件

来源：[本地 PDF](../../references/papers/2505.13159v1.pdf)

- **为什么提出**：通用处理器若逐元素把 MXFP8 扩为 FP32、乘 scale 后再 FMA，指令和转换开销很高。
- **格式/接口**：一条指令消费两个打包的 8×FP8 向量、各自 INT8/E8M0 block scale，以及 FP32 accumulator；支持 MXFP8 E4M3/E5M2。
- **实际计算**：内部形成 FP9(E5M3) 乘积，用 95-bit exact fixed-point early accumulator 合并点积与旧 FP32 累加值，RNE 后输出 FP32。
- **算法边界**：它实现 MX 点积语义，不选择 W/A/KV；也不量化非线性。（PDF pp. 1–5）

### L27. FP4 All the Way: Fully Quantized Training of LLMs（2025）

来源：[本地 PDF](../../references/papers/2505.19115v2.pdf)

- **为什么提出**：已有 FP4 训练通常只覆盖 forward 或依赖较高精度 backward/update；目标是三个训练 GEMM 都用 FP4 数值。
- **方法/格式**：NVFP4 元素 E2M1，16 元素共享 E4M3 scale（对比 MXFP4 的 block-32/E8M0）；Fprop 的 W/A 用 round-to-nearest，Dgrad/Wgrad 对 gradient 等敏感输入使用 stochastic rounding。
- **位置**：三类 GEMM（Fprop、Dgrad、Wgrad）量化；optimizer/master 与非 GEMM 敏感算子保留较高精度；KV 不适用。
- **实际计算警告**：实验在 Gaudi2 上模拟 FP4，Gaudi2 没有原生 FP4 MAC，所以论文证明的是数值可训练性，不是 FP4 硬件速度。
- **异常值/稳定性**：block-16 hierarchical scale 缩小局部范围；SR 降低梯度无偏性损失；没有平滑/旋转。（PDF pp. 3–10）

### L28. SeVeDo: SVD-Enhanced Vector Dot Product for 4-bit LLM Acceleration（2025）

来源：[本地 PDF](../../references/papers/2512.12930v2.pdf)

- **为什么提出**：纯 W4A4 易损精度，而全高精度 scale/dequant 又造成大量浮点操作；希望将少量敏感成分结构化隔离。
- **方法**：把 W 分为高精度低秩 SVD 分量和 INT4 residual；residual 使用 hierarchical group quantization：G128 FP16 base scale + G32 2-bit exponent shift。
- **格式/位置**：residual W4；低秩路径按敏感通道混合 W8A16 与 W4A8；KV/非线性不是重点。
- **实际计算**：bit-sliced integer vector dot；多数 subgroup scale 通过移位实现，只保留较少 FP scale/累加。
- **异常值**：SVD 低秩路径承接难量化结构，敏感通道进入更高精度。（PDF pp. 1–6）

### L29. High-Performance W4A16 Matrix Multiplication on Ascend NPUs（2026）— NPU kernel

来源：[本地 PDF](../../references/papers/2601.16536v2.pdf)

- **为什么提出**：Ascend AIC（Cube）和 AIV（Vector）分离，W4A16 若先完整反量化会产生额外 global-memory 往返，难以达到 4× 理论收益。
- **格式**：W 为 uniform affine INT4 存储，A 为 FP16，输出 FP16。
- **实际计算**：AIV 解包/反量化 INT4→FP16 并写 workspace；AIC 执行 FP16 GEMM，L0C/partial 采用 FP32；Split-K partial 由 AIV 归约后 cast FP16。
- **位置**：线性层 W-only；KV/非线性未量化。
- **关键结论**：论文测得相对原生 FP16 上限约 1.48×；W4 容量收益不自动变成 W4 计算吞吐。（PDF pp. 1–7）

### L30. TransDot: A Unified Transprecision Dot-Product Unit（2026）— 算术单元

来源：[本地 PDF](../../references/papers/2605.07245v1.pdf)

- **为什么提出**：分别放置 FP32/FP16/FP8/FP4 单元面积低效，需要共享 datapath 的可重构 dot-product。
- **格式**：1-way FP32 E8M23、2-way FP16 E5M10、4-way FP8 E4M3、8-way FP4 E2M1。
- **实际计算**：低精度乘积在统一对齐/累加网络中汇合，结果进入 FP32/FP16 accumulator；不是先把所有输入恢复成 FP32 再乘。
- **算法边界**：不提供 scale/calibration，也不指定 W/A/KV/非线性，是硬件 primitive。（PDF pp. 1–5）

### L31. Quant.npu: NPU-Friendly Post-Training Quantization for LLMs（2026）

来源：[本地 PDF](../../references/papers/2605.20295v1.pdf)

- **为什么提出**：许多 GPU 量化依赖 per-token 动态 scale、在线 Hadamard/rotation 或 FP16 fallback；移动 NPU 上这些操作昂贵，且会打断纯整数流水线。
- **方法**：per-channel symmetric W、per-tensor static symmetric A；两阶段学习等价 rotation 与静态 scale/zero。保留可离线融合的 R1/R2，移除需在线执行的 R3/R4；STE 优化量化误差。
- **位置/格式**：W/A 可 INT4/8；线性输出和 KV 固定 INT8；SiLU 等非线性中间量固定 INT16，embedding 也使用 INT16；约 10% 敏感 down-proj 输入通道可 INT16，其余 INT8。
- **实际计算**：部署在 Snapdragon/SM8650 NPU 的静态纯整数流水线；无运行时 amax、FP online rotation 或普遍 FP16 fallback。
- **异常值**：离线学习正交旋转；对近 Gaussian 的旋转低比特 tensor 采用 mean-based 初始化，对重尾高比特 tensor 用 min-max；再以相对误差选择混合精度通道。（PDF pp. 3–10）

### L32. ShapeShifter: Enabling Fine-Grain Data Width Adaptation in DNN Accelerators（2020）— 无损容器宽度

来源：[本地 PDF](../../references/papers/3352460.3358295.pdf)

- **为什么提出**：已量化 tensor 在不同层/组仍有不同有效位宽，固定容器会传输前导符号位。
- **方法**：每 16–256 值一组，选择能 **无损** 表示原量化整数的最小容器宽度；W 宽度静态，A 可动态。
- **实际计算**：SStripes 风格 bit-serial 乘法，最大约 36-bit 累加；保持原量化值不变。
- **算法边界**：论文明确不是新的 quantizer；它是对任意 INT8/INT16/范围感知量化结果的二次无损打包。（PDF pp. 1–5）

### L33. OCP Microscaling Formats (MX) v1.0 Specification（2023）— 标准

来源：[本地 PDF](<../../references/papers/OCP_Microscaling Formats (MX) v1.0 Spec_Final.pdf>)；[OCP 官方版本](https://www.opencompute.org/documents/ocp-microscaling-formats-mx-v1-0-spec-final-pdf)

- **格式定义**：block size 32；共享 E8M0 scale `X`（2 的幂）；private elements 为 MXFP8 E4M3/E5M2、MXFP6 E2M3/E3M2、MXFP4 E2M1、MXINT8。
- **转换**：由 block 最大绝对值/exponent 决定共享 scale，再对 private element 舍入/饱和；最低要求 round-to-nearest-even。
- **点积语义**：`X_A X_B Σ(P_Ai P_Bi)`；通用 dot product 建议/要求产生 FP32 结果，但内部乘积精度、归约树和顺序有实现自由度。
- **位置**：标准不指定 W/A/G/KV/非线性由谁采用；应用论文通常把 GEMM operands 设为 MX，非线性和归约保留 BF16/FP32。
- **异常值**：32 元素共享 scale 是结构性范围控制，不含学习平滑/旋转。（PDF pp. 9–16）

## 3. 自主补充的一手文献

以下文献用于补足本地集合中缺失的整数非线性、NF4 微调、稀疏异常值、旋转量化与大规模 FP8 训练主线。

### E01. I-BERT: Integer-only BERT Quantization（2021）

来源：[arXiv:2101.01321](https://arxiv.org/abs/2101.01321)

- **为什么提出**：早期 Transformer INT8 仍在 GELU、softmax、LayerNorm 回到 FP，无法在纯整数 ARM/NPU/Tensor Core 流水线上端到端执行。
- **方法**：QAT 将线性层 W/A 量化为 INT8；用整数多项式/移位近似 GELU 与 exp/softmax，并推导整数 LayerNorm（含整数平方根）。
- **实际计算**：INT8 线性层以宽整数（通常 INT32）累加；非线性只用整数算术和 requantization，不发生 FP fallback。
- **异常值**：重点是非线性近似而非 LLM channel outlier；适用于 BERT/RoBERTa，并非现代生成式 LLM 的直接无损配方。

### E02. ZeroQuant（2022）

来源：[arXiv:2206.01861](https://arxiv.org/abs/2206.01861)

- **为什么提出**：大 Transformer PTQ 既要低校准成本，也要避免 quant/dequant kernel 抵消 INT8 收益。
- **方法**：fine-grained hardware-friendly quantization + layer-by-layer knowledge distillation（无需原训练数据）+ 融合后端；W 使用 group-wise scale，A 使用 token-wise dynamic scale。
- **格式/位置**：无损级配置 W8A8；更激进配置 FFN W4、attention W8、A8。KV/非线性不是核心，算子边界保持较高精度。
- **实际计算**：INT8 配置使用整数 GEMM；W4 混合配置的具体乘法路径取决于后端支持，不能只由“W4”标签推断。
- **异常值**：细粒度 scale 限制局部范围，LKD 补偿块误差；不使用旋转。

### E03. QLoRA: Efficient Finetuning of Quantized LLMs（2023）

来源：[arXiv:2305.14314](https://arxiv.org/abs/2305.14314)

- **为什么提出**：全参数 BF16/FP16 微调 33B/65B 模型显存过高，而直接训练 4-bit 基座不稳定。
- **方法/格式**：冻结基座 W 以 4-bit NormalFloat（NF4）保存；NF4 的 16 个码点按标准正态分布等概率区间构造。每 64 个权重一个 FP32 quantization constant，再用 8-bit 对这些 constants 做 double quantization；只训练 BF16 LoRA adapter，paged optimizer 处理峰值。
- **位置**：只压缩 frozen base weights；A、G、adapter、非线性、KV 不以 NF4 执行。
- **实际计算**：NF4 权重按块反量化到 BF16（或配置的 16-bit compute dtype），再与 BF16 A 做矩阵乘；NF4 是存储/码本格式，不是原生 NF4 MAC。
- **异常值**：利用预训练 W 近似正态的分位数码本提高 4-bit 信息效率；不处理 activation outlier。

### E04. SpQR: A Sparse-Quantized Representation for Near-Lossless LLM Weight Compression（2023）

来源：[arXiv:2306.03078](https://arxiv.org/abs/2306.03078)

- **为什么提出**：3/4-bit W-only 中少数权重会产生极大 Hessian-weighted 误差，并且这种异常值呈不规则稀疏分布。
- **方法/格式**：把普通 W group-wise 量化为 3/4 bit；把敏感 outlier W 与部分 scale/zero 元数据以更高精度稀疏保存，使用二阶误差信息决定隔离对象。
- **位置**：W-only；A/KV/非线性为 FP16。
- **实际计算**：稠密低比特权重解码路径与稀疏高精度修正路径相加；不是纯 3-bit MAC。
- **异常值**：显式稀疏隔离，代表“不要变换分布，而是把难点拆出来”的路线。

### E05. OmniQuant（2023）

来源：[arXiv:2308.13137](https://arxiv.org/abs/2308.13137)

- **为什么提出**：手工 clipping/smoothing 参数在 W2/3/4 与 W4A4 等极低位设置下不稳，但完整 QAT 又太贵。
- **方法**：用少量 calibration data 做 block-wise reconstruction；Learnable Weight Clipping（LWC）学习 W 上下裁剪边界，Learnable Equivalent Transformation（LET）学习等价 scale/shift，把 A outlier 难度迁移到 W。
- **格式/位置**：支持 W2/3/4-A16、W4A4、W6A6；KV 和非线性通常高精度。
- **实际计算**：算法输出整数权重/激活及 scale；是否为原生 INT4 GEMM取决于部署 kernel。论文的算法精度结果不能自动视为所有设备都有 W4A4 加速。
- **异常值**：LET 是 SmoothQuant 从闭式/网格超参数走向可学习等价变换，LWC 同时压制 weight outlier。

### E06. Atom: Low-bit Quantization for Efficient and Accurate LLM Serving（2023/2024）

来源：[arXiv:2310.19102](https://arxiv.org/abs/2310.19102)

- **为什么提出**：W4A16 仍用浮点 MAC；纯 W4A4 又被 activation outlier 和 group scale 开销破坏；服务批量下需要真正用到 INT4 Tensor Core。
- **方法/格式**：W/A 主体 symmetric INT4，校准识别的少数异常通道用 INT8；离线同时重排 W，在线 A 重排融合到前算子；W 用 GPTQ，A 每次动态 group quant。KV 用 per-head asymmetric INT4。
- **非线性**：块边界及 attention softmax 为 FP16。
- **实际计算**：每个 group 的 INT4×INT4 Tensor Core 部分和先产生宽整数结果，再在 CUDA Core 反量化为 FP16并跨 group 累加；KV4 载入后反量化，attention 用 FP16。
- **异常值**：混合 INT4/INT8 + 通道重排，兼顾准确率和规则内存访问。

### E07. QuaRot: Outlier-Free 4-Bit Inference in Rotated LLMs（2024）

来源：[arXiv:2404.00456](https://arxiv.org/abs/2404.00456)

- **为什么提出**：分流异常通道会产生混合精度 kernel；希望用等价正交变换一次性消除 W/A/KV outlier，实现端到端 W4A4KV4。
- **方法**：把随机 Hadamard rotation 吸收到相邻 W/Norm 中；对 down/out projection 等仍需在线 Hadamard 的位置执行快速变换；W 默认 GPTQ，A symmetric per-token RTN，KV INT4。
- **位置/格式**：所有线性 W INT4，线性前 A INT4，KV INT4；RMSNorm core 用 FP32，块间信号/量化前后用 FP16。
- **实际计算**：CUTLASS INT4×INT4 Tensor Core→INT32，立即乘 scale/cast FP16；online Hadamard 在 FP32（论文也验证 FP16）；KV attention 反量化后执行。
- **异常值**：随机旋转把固定异常通道扩散到全部维度，无需保留高精度 channel。

### E08. SpinQuant: LLM Quantization with Learned Rotations（2024）

来源：[arXiv:2405.16406](https://arxiv.org/abs/2405.16406)

- **为什么提出**：QuaRot 的随机 rotation 之间精度差可达两位数百分点，随机选取并非最优。
- **方法**：枚举 Transformer 中保持全精度函数不变的 rotation 参数化，用 calibration loss 与 Cayley/正交优化学习 rotation，再量化 W/A/KV。
- **格式/位置**：核心报告 W4A4KV4；非线性/归一化仍留高精度或在等价变换边界执行。
- **实际计算**：量化结果需要 W4A4KV4 后端；SpinQuant 的创新是学习 rotation，不是新的 4-bit MAC 编码。没有具体原生 kernel 证据时不应单独宣称硬件加速比。
- **异常值**：从“随机正交扩散”演进为“面向量化误差学习正交基”。

### E09. FP8-LM: Training FP8 Large Language Models（2023）

来源：[arXiv:2310.18313](https://arxiv.org/abs/2310.18313)

- **为什么提出**：Transformer Engine 主要把 GEMM 输入降到 FP8，但 gradient、optimizer、collective communication 仍高精度，端到端显存/通信收益有限。
- **方法**：三档自动混合精度逐步把 FP8 扩到 compute、gradient communication、master/optimizer；以 precision decoupling 决定哪些状态可降位，并对 all-reduce gradient 自动缩放防溢出/下溢。
- **格式/位置**：FP8 GEMM 与通信；可用 FP8 master、FP8 first moment + FP16 second moment 等组合，论文消融显示过度把所有 optimizer state 都压 FP8 会发散。敏感非线性保留 BF16/FP32。
- **实际计算**：H100 原生 FP8 Tensor Core GEMM，输出/累加和 optimizer update 使用更高精度；不能把“FP8-LM”理解为训练状态全是 FP8。
- **异常值**：自动 scale 与变量级 precision decoupling，而非通道旋转。

### E10. DeepSeek-V3 FP8 Mixed-Precision Training（2024）

来源：[DeepSeek-V3 Technical Report, arXiv:2412.19437](https://arxiv.org/abs/2412.19437)

- **为什么提出**：超大 MoE 训练中 tensor-wise FP8 scale 被 outlier 主导，H800 FP8 Tensor Core 的有效累加精度在长 K 上也不足。
- **方法/格式**：所有 Fprop/Dgrad/Wgrad GEMM operands 采用 E4M3；A 为 1×128 tile-wise online quant，W 为 128×128 block-wise online quant。master W 与累计 G 为 FP32，AdamW moments 为 BF16；norm、attention、embedding、output head、gating 为 BF16/FP32。
- **特殊存储**：部分 attention 后 activation cache 用定制 E5M6；SwiGLU 输入以细粒度 FP8 缓存并在 backward 重算；MoE dispatch activation/gradient 以 FP8 通信。
- **实际计算**：H800 WGMMA 先以约 14-bit 有效内部精度累加；每 128 个 FP8×FP8 乘积（4 个 WGMMA）把部分和提升到 CUDA Core FP32 register，乘 per-group scale 后继续 FP32 累加；输出 BF16/FP32。
- **异常值**：细粒度 tile/block scale；全部使用 E4M3，以局部共享尺度代替 E5M2 的额外 exponent。论文特别报告 Dgrad 的 token-correlated outlier 使简单 128×128 block A/G 量化发散。

### E11. NVIDIA NVFP4 / Blackwell 原生格式与执行支持（官方资料）

来源：[NVIDIA Transformer Engine NVFP4](https://docs.nvidia.com/deeplearning/transformer-engine/user-guide/features/low_precision_training/nvfp4/nvfp4.html)；[CUTLASS Blackwell GEMM](https://docs.nvidia.com/cutlass/latest/media/docs/cpp/blackwell_functionality.html)

- **格式**：private element 为 E2M1（最大幅值 6）；每 16 元素共享 E4M3 local scale，整个 tensor 再乘 FP32 global scale。训练默认 W 采用 16×16 2D scale，A/G 采用 1D block-16 scale。
- **硬件**：SM100/Blackwell `tcgen05.mma` 原生支持 NVFP4 与 OCP MXFP4 block-scaled MMA；NVFP4 scale 为 UE4M3、向量粒度 16，MXFP4 scale 为 UE8M0、粒度 32。
- **实际计算口径**：这类硬件才使“FP4 保存格式”与“FP4 MMA operand”真正一致；输出/累加仍应单独查看具体 instruction/kernel 的 accumulator 配置。
- **算法边界**：NVFP4 是格式+recipe+硬件能力，不单独规定模型哪些非线性、KV 或 optimizer state 必须 FP4。

## 4. 逐篇阅读得到的共性结论

1. **W4 不等于 4-bit MAC**：GPTQ/AWQ/QLoRA/Ascend W4A16 都可能先解码到 FP16；QServe 则把 W4 转为 INT8 后用 INT8 Tensor Core；只有 Atom/QuaRot 等才明确使用 INT4×INT4，Blackwell NVFP4 才提供原生 FP4 MMA。
2. **KV2/4 通常是压缩和带宽格式**：KIVI、KVQuant、QServe、Atom 的 attention 核多在载入后反量化，softmax 与点积仍用 FP16/FP32。
3. **非线性是整数端到端的最后边界**：主流 LLM PTQ 把 LayerNorm/RMSNorm、softmax、GELU/SiLU 保留 FP16/BF16/FP32；I-BERT 与 Quant.npu 才系统地给出整数近似/INT16 中间格式。
4. **异常值处理从“保留”演进为“重参数化”**：LLM.int8/SpQR/KVQuant 分流；SmoothQuant/AWQ/OmniQuant 等价缩放；QuaRot/SpinQuant/FlashAttention-3 做旋转；MX/NVFP4/DeepSeek-V3 用细粒度共享尺度；SeVeDo 用低秩结构隔离。
5. **训练低精度的瓶颈常在累加与状态，而非乘法**：FP16/BF16/FP8/FP4 论文都保留更宽 accumulator、master weight、optimizer 或敏感归约；DeepSeek-V3 更明确展示 Hopper FP8 内部累加不足时需要周期性提升到 CUDA Core FP32。
